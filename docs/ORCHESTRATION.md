# 오케스트레이션 프로토콜 — 지휘관 ↔ 행동대장 1~6

> 총괄 지휘관(Claude)이 컴퓨터유즈 코덱스 세션 6개(네이버마스터 행동대장 1~6)에게
> **사람 개입 없이(핸즈오프)** 지시를 내리고 보고를 받는 방법을 정의한다.

## 1. 기본 구조: 파일 큐

행동대장 세션들과 지휘관은 alfredo 맥북의 **공유 디렉터리(이 저장소의 `ops/tasks/`)** 를 통해서만 대화한다.
채팅창에 사람이 복사-붙여넣기 하는 일은 없다.

```
ops/tasks/
├── agent-1/
│   ├── inbox/      ← 지휘관이 작업지시서를 넣는다
│   ├── doing/      ← 행동대장이 착수 시 지시서를 이동 (잠금 역할)
│   └── done/       ← 행동대장이 결과보고서 + 증빙을 넣는다
├── agent-2/ … agent-6/   (동일 구조)
└── broadcast/      ← 전 대장 공통 공지 (정책 변경 등)
```

- **행동대장 루프**: 각 코덱스 세션은 시작 시 단 하나의 상주 지시를 받는다 —
  *"`ops/tasks/agent-N/inbox/`를 감시하라. 지시서가 오면 `doing/`으로 옮기고 수행하라.
  끝나면 보고서와 스크린샷을 `done/`에 넣어라. 이를 무한 반복하라."*
- **지휘관 루프**: 지휘관은 `done/`을 폴링해 보고서를 평가하고, 다음 지시서를 `inbox/`에 생성한다.
  지휘관이 원격(클라우드 세션)일 경우 git push/pull로 동기화하고,
  alfredo 로컬에서 돌 경우 파일시스템을 직접 본다. **로컬 구동을 기본으로 한다** (지연 최소화).

## 2. 작업지시서 포맷

파일명: `T{YYYYMMDD}-{순번}_{요약}.md` (예: `T20260611-003_blog_post_publish.md`)

```markdown
---
task_id: T20260611-003
issued_by: commander
agent: agent-3
type: blog_publish          # 작업 유형 (아래 카탈로그 참조)
priority: normal            # normal | urgent
deadline: 2026-06-11T14:00+09:00
retry_of: null              # 재시도면 원 task_id
---
## 목표
(한 문단: 무엇이 완료 조건인가)

## 입력
- 초안 파일: ops/state/drafts/post_0042.html
- 이미지: ops/state/media/0042/*.jpg
- 승인 토큰: APPROVAL-0042-PASS   ← 자동승인 게이트가 발급. 없으면 게시 금지.

## 절차
1. (브라우저 프로필 'naver-main'으로) blog.naver.com 접속 …
2. …

## 보고 요구사항
- 게시 URL
- 게시 직후 전체 페이지 스크린샷
- 이상 징후(캡차, 경고 팝업) 발생 여부
```

## 3. 결과보고서 포맷

파일명: `T20260611-003_REPORT.md` + 증빙 파일들 (같은 `done/` 폴더)

```markdown
---
task_id: T20260611-003
agent: agent-3
status: success             # success | partial | failed | blocked
started: 2026-06-11T13:02+09:00
finished: 2026-06-11T13:11+09:00
---
## 결과
- 게시 URL: https://blog.naver.com/…
- 증빙: T20260611-003_screen1.png

## 특이사항
- 없음 / (캡차 출현, 로그인 풀림 등 → status: blocked 으로 기록)
```

`status: blocked`(캡차·로그인 풀림·네이버 경고)는 지휘관이 **즉시 해당 계열 작업 전체를 일시정지**하고
아침 보고(긴급 시 즉시 카톡)에 올린다.

## 4. 행동대장 역할 분담

| 대장 | 호출명 | 담당 | 비고 |
|---|---|---|---|
| 1 | 영상반 | 유튜브 감지 확인, yt-dlp 다운로드, ffmpeg 프레임 추출 | 브라우저 불필요한 로컬 작업 위주 |
| 2 | 편집반 | 캡처 선별·크롭, 이미지 정리, 초안 조립 보조 | |
| 3 | 블로그반 | 네이버 블로그 게시 + 블로그 댓글 응대 | 네이버 프로필 사용 |
| 4 | 카페반 | 네이버 카페 게시 + 카페 댓글 응대 | 네이버 프로필 사용 |
| 5 | 정보반 | 크리에이터 어드바이저·카페 통계 수집, 게시물 반응 수집 | 네이버 프로필 사용 |
| 6 | 검증반 | 게시 결과 실제 확인(QA), 링크 클릭 검증, 실패 건 재시도 | 비로그인 브라우저로 독자 시점 확인 |

### 네이버 동시 접속 규칙 (중요)
동일 네이버 계정으로 여러 세션이 **동시에** 로그인 행동을 하면 보안 감지에 걸린다.
- 로그인된 브라우저 프로필 `naver-main`은 **하나**만 두고, 대장 3·4·5가 **시간대를 나눠 순차 사용**한다.
  지휘관은 같은 시간대에 네이버 로그인 작업을 두 대장에게 동시에 내리지 않는다 (`ops/state/naver_lock` 파일로 상호배제).
- 대장 6(검증반)은 로그아웃 상태 브라우저만 사용한다.

## 6. 장애 처리

- 보고서가 deadline+30분까지 없으면 지휘관이 `failed(timeout)` 처리 후 같은 지시를 재발행(최대 2회), 그래도 실패하면 대장 6에게 이관.
- `ops/state/PAUSE` 존재 시: 모든 대장은 진행 중 작업만 마무리하고 신규 inbox를 무시한다.
- 지시서·보고서는 처리 후에도 삭제하지 않고 `done/`에 영구 보존한다 (감사 추적).
